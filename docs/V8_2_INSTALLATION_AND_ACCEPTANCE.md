# TrawellBeyond V8.2 - Installation and Live Acceptance

**Baseline:** V8.1.2. **Output:** V8.2 (both launch and next enhancement scope).

## Apply the code

1. Save a copy of your current V8.1.2 project, original `.env.local`, `firebase.json` and Firestore rules.
2. For an existing checkout of **V8.1.2**, extract `TrawellBeyond_V8_2_Changed_Files_Only.zip` into its project root, preserving folders. Do not create another nested source folder.
3. Alternatively, extract `TrawellBeyond_V8_2_Full_Project.zip` as the new complete source. Copy your existing private local `.env.local` into it. **Do not put secrets into chat or a ZIP.**
4. In PowerShell or a terminal inside the project root, run:

```powershell
npm install
npm test
npm run check:syntax
npm run verify:frontend
npm run audit:journey:v82
npm run bundle:enquiries
npm run build
```

Optional isolated browser regression (requires Python Playwright and Chromium installed):

```powershell
python tests/browser-v82-companion.py
```

The isolated test uses a **fixture**, not real Firebase data. Inspect the generated screenshots on desktop and mobile.

## Firebase checks and deployment

V8.2 changes `firestore.rules`. Deploying only the frontend is insufficient and can cause `permission-denied` on new enquiries.

1. In Firebase Console > Authentication > Sign-in method, ensure **Anonymous** sign-in is enabled for visitor enquiries. Keep Microsoft sign-in enabled for Admin.
2. Verify your Firebase project ID using your existing `firebase.json` / `.firebaserc` / CLI project selection. Do not deploy to a guessed project ID.
3. Back up your live rules and deploy the new rules from the correct project directory:

```powershell
firebase use
firebase deploy --only firestore:rules
```

4. Deploy the Next.js site with **your current hosting architecture** (Firebase App Hosting, existing CI deployment, or other Next.js hosting). `firebase deploy --only hosting` is not a substitute for an SSR App Hosting deployment unless that is how your project was actually configured.
5. Confirm that the bundled `public/enquiry-bridge.bundle.js` is generated by `npm run bundle:enquiries` and deployed. It supplies the public Web SDK bridge to the static destination/experience/journey templates.
6. If the deployment fails, restore the V8.1.2 frontend **and the prior Firestore rules together**, then retest existing enquiries. Avoid leaving mismatched frontend and rules active.

## First acceptance scenario

- Browse homepage, `/journey-match`, `/my-journey`, `/create` and a published destination, experience and journey.
- Open **Ask TrawellBeyond**. Choose Togetherness; optionally provide travelers, destination, date, interests, pace, budget guidance; view CMS-grounded suggestions. Unpublished content must not appear.
- Choose **Talk to our team**, provide a test name and phone, check consent and submit. Verify a reference and a single new lead in Admin > **Journey Companion Inbox**.
- Confirm Admin can assign to a Publisher, assigned Publisher sees only their assignment, Editor and Media Assistant cannot access leads.
- Change progress from New > Reviewing > Contacted. Open `/my-enquiries` in the **same visitor browser** and refresh status. The enquiry reference should be inaccessible to another browser/session.
- Save a published journey to My Journey, compare two journeys, share a URL and inspect the URL to confirm it contains only public slugs, not private details.
- Use `/customize?journey=<published-slug>` and submit a requested day change to the team. Test that edits never silently replace the published itinerary.
- Inspect `/insider/<published-destination-slug>` for correct CMS-backed practical information, official links and a clear review date. Avoid shipping unsupported visa/entry advice.
- Check 320px, 390px, 768px and 1440px layouts, keyboard accessibility, reduced motion, performance and actual imagery.

## Important operational limitations

- The initial Journey Companion is **guided, deterministic matching**, not an unrestricted AI language model. It makes no verified-price or live-inventory claims.
- A WhatsApp link facilitates **manual adviser communication**. No WhatsApp API automation, approved templates or automatic messages are part of this release.
- The enquiry tracker uses the existing browser's Firebase visitor session. A reference number is never a password; there is no cross-device login or customer portal in V8.2.
- Image completion remains a **separate acceptance requirement**. V8.2 does not manufacture missing photographs.
- Local tests passed, but the full production build, Firebase emulator security tests, deployment and real-device acceptance remain **unverified** in the source-development environment.
